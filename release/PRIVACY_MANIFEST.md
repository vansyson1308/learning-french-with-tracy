## App-level manifest (generated by `expo prebuild` from `app.json`)

`ios.privacyManifests` → `ios/LingoLessons/PrivacyInfo.xcprivacy`, added to
the Resources build phase (verified in `project.pbxproj`):

| Key | Value | Why this is true |
|---|---|---|
| NSPrivacyTracking | false | no tracking, no ATT prompt, no ad SDK |
| NSPrivacyTrackingDomains | [] | no network requests at all |
| NSPrivacyCollectedDataTypes | [] | nothing transmitted off device by the app |
| FileTimestamp | `C617.1` | React Native / AsyncStorage inspect timestamps of files inside the app container (declared by their own manifests; the app binary links them statically) |
| UserDefaults | `CA92.1` | Expo modules read/write the app's own defaults (settings, splash state) |
| SystemBootTime | `35F9.1` | React Native timers / expo-device use uptime for elapsed-time measurement |
| DiskSpace | `E174.1` | expo-file-system checks free space before writing a backup file |

No other reason code is declared. In particular no `ActiveKeyboards`
category (the app never enumerates keyboards) and no `NSPrivacyCollectedDataTypes`
entry — declaring either would be false.

## Verification performed here

- `expo prebuild --no-install --platform ios` on SDK 57 generated the file with
  exactly the four entries above and no collected-data entries.
- `scripts/__tests__/permissions.test.ts` pins the `app.json` source so the
  generated manifest cannot drift silently.
