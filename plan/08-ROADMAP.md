# Roadmap — phases, milestones, gates

Each milestone has a prompt in `plan/prompts/` that a Claude Code session executes end-to-end. The coordinator (Claude in the chat) reviews the result against the **Definition of Done** before the next prompt is issued. Phases are sequential; milestones inside a phase can run in parallel when marked ∥.

Rules that apply to every milestone (also in `CLAUDE.md`):
- Work on a branch `phase-N/<milestone>`; open a PR to `main`; CI must be green (tsc, lint, bun tests in 5 TZ lanes, jest, `content:check`, `audio:check`, `release:identity`, web export + e2e).
- French (`fr-en`) behaviour must stay byte-identical unless the milestone says otherwise — golden tests enforce it.
- No network, no analytics, no secrets, no licence-unknown data. Every new source/voice goes into `content/sources/registry.json` + `ATTRIBUTIONS.md`.
- Docs are part of the deliverable: update `release/*`, `docs/USER_GUIDE.md`, `KNOWN_LIMITATIONS.md` when behaviour changes.

## Phase 0 — Ship an APK now (≈1–2 days)  → prompt `P0`
Goal: a release-signed APK of the current `main` on the owner's phone, built locally on Windows; the owner key created; RC3 recorded.
- M0.1 Windows toolchain (bun, Android SDK 36 / build-tools 36.0.0 / NDK 27.1 / cmake, JDK 17) — `plan/scripts/setup-windows-android.ps1`.
- M0.2 Clone to `C:\src\lft`, install, gates, prebuild, `assembleRelease`, post-sign with owner key, `apksigner verify`, badging checks, `adb install`.
- M0.3 Cheap fixes in the same RC (small PR): onboarding default → `fr-en`; course guards on `/goals`, `/placement/*`, `/checkpoint/*`, FR-only lesson ids; `LEXICON_LICENSE.md` + registry notes updated to 126 lexemes; delete `src/content/pack.json`; fix `scripts/lib/audio.ts` path separators; add `.gitattributes` (`* text=auto eol=lf`); shuffle MCQ options in lessons with the seeded RNG.
- M0.4 Owner runs Packets 1–3 (install/launch/fresh/core) and reports; results recorded in `DEVICE_ACCEPTANCE.md`, `RC_HISTORY.md`, `ANDROID_SIGNING.md`.
**DoD:** APK installs and runs on the phone; `apksigner verify` Verifies with the owner key; Packets 1–3 PASS; CI green on the tagged commit.

## Phase 1 — Multi-course engine (≈2–3 weeks)  → prompts `P1a`…`P1d`
Goal: remove the ~60 `fr-en` hardcodes; any course can opt into any capability; French unchanged.
- M1.1 (`P1a`) Golden tests: snapshot French compile outputs + runtime scenarios (session, Today composer, evidence, estimate) so refactors are provable.
- M1.2 (`P1b`) `CourseProfile` registry generated by the compiler; `capabilities.ts` replaced; `src/lib/languages/<code>.ts` + `scripts/lib/languages/<code>.ts` plugins (articles, numbers, normalise, tokenise, fold); per-course artifact loaders with static requires; all runtime `"fr-en"`/`FR_COURSE_ID` checks replaced; route guards; `courseId` threaded explicitly (store `submitEvidence`, controller, sources, composer).
- M1.3 (`P1c`) Schema parameterisation: `language: string` cross-checked with pack `targetCode`; id regexes `${lang}…`; `recognitionLocale` BCP-47; examples `{target, native}` → `translations` keyed by nativeCode; gender adds `neuter`; grammar tables generic (paradigm cells per language); compiler loops over `content/<target>/`; validators take a language plugin; reception/speech/writing/interaction validators mirror-check every course that has them.
- M1.4 (`P1d`) Persistence v4: `assessment` per course; `reviewLog` + `cards` moved to an expo-sqlite learner DB (AsyncStorage keeps settings); backup envelope v2 (accept v1); migration tests with historical personas; soak test re-run.
**DoD:** golden tests unchanged for French; `es-en` can be switched to FSRS by a capability flag with a migration test; a dummy `xx-en` course with every rich layer compiles and validates; CI green.

## Phase 2 — Vietnamese UI & native-language content model (≈2 weeks)  → prompts `P2a`, `P2b`
- M2.1 (`P2a`) i18n chrome: `expo-localization` + typed `t()` catalogue (`vi`, `en`), ~500 strings incl. accessibility labels, lib messages refactored to keys, `uiLanguage` setting + Profile picker, Vietnamese diacritics QA (line height, uppercase buttons), e2e selectors → testIDs; privacy policy + site in both languages.
- M2.2 (`P2b`) Native-language content: pack schema gains `nativeCode` everywhere it matters; `fr-vi` produced from `fr-en` by a translation script (glosses, options, questions, guidebooks, concept prose, can-do, instructions — all Vietnamese) with a review checklist; Licences/Privacy screens language-aware.
**DoD:** app runs fully in Vietnamese with `fr-vi`; `fr-en` unchanged; screenshots in both languages.

## Phase 3 — Generic content pipeline + first new Vietnamese-source course `es-vi` (≈4–6 weeks)  → prompts `P3a`…`P3d`
- M3.1 (`P3a`) Lexicon ETL v2: kaikki + FrequencyWords/wordfreq (+ SUBTLEX-PT, JMdict, CC-CEDICT, NIKL, openjlpt, hsk30 anchors) → `content/<lang>/lexicon/` for **all 8 targets (+ en)** with Vietnamese glosses, fail-closed source manifests, licence registry; first full output `es` (~800 lemmas), skeletons for the rest.
- M3.2 (`P3b`) Audio pipeline v2: engine abstraction (Piper / Kokoro / MeloTTS), licence gate, two-voice casts, ASR audit with language plugin (CER for ja/zh), reception pipeline parameterised; first run `es`; voice selection (canary) recorded for all 8 targets.
- M3.3 (`P3c`) Authoring toolkit: LLM-assisted generators emitting drafts that must pass validators + a native (Vietnamese) review checklist; Vietnamese style guide for learner-facing prose; course blueprint with French's counts.
- M3.4 (`P3d`, parametrised `--target es`) Author `es-vi` A1 to French parity + DELE A1 exam track (the exam-track engine is built here and reused).
- M3.5 (`P3e`) Harden the template on `es-vi`: DELE A1 2020 model, daily new-words stream from a lexical syllabus, lesson-shape and variety gates, tiered review (Tier-1 files, LanguageTool, back-translation), locale default course.
- M3.6 (`P3f`) QC follow-up + RC4: audio size budget (32 kbps, syllabus-only lexicon audio, 12 MB per language, `release/ASSET_DELIVERY.md`), topic→unit syllabus map, vosotros, DELE checked; RC4 (build 2) signed by the owner and upgrade-tested over RC3 on the phone.
**DoD:** `es-vi` passes every validator and the claim gate; audio generated and provenance closed; device walk; RC with Vietnamese UI + `fr-vi` + `es-vi`.

**Order after Phase 3 (coordinator decision 2026-10-22):** P4a → **P5b graded stories** → P3d(de/it/pt) → P4b (with Hán-Việt) → P4c–f → the rest of P5 → P6. Graded stories move ahead of the next languages because they are the context layer the daily-words stream needs (P3f lint `syllabus-context`: 404 of 613 Spanish daily words have no sentence yet) and every language reuses them.

## Phase 4 — The remaining courses, all from Vietnamese (≈12–20 weeks)  → prompts `P4a`…`P4g`
- M4.1 (`P4a`) Fix inherited packs (ja/zh/ko/it defects, romanization rendering, de guidebook, es voice) and retire `*-en` basic packs from onboarding as `-vi` courses ship.
- M4.2 (`P3d --target de|it|pt`, ∥) `de-vi`, `it-vi`, `pt-vi` with Goethe A1 / CILS A1 / CAPLE A1 tracks — same template as `es-vi`; German adds neuter + case concepts, Portuguese pt-BR primary.
- M4.3 (`P4b`) Language plugins for ja/zh/ko: segmentation, readings (furigana/pinyin/RR), script primers with Vietnamese explanations, tokeniser/normaliser for grading, paradigm cells — **plus Hán-Việt readings**: every kanji/hanzi/hanja word shows its Sino-Vietnamese reading (学生 → học sinh; 図書館 → đồ thư quán; 학생 學生 → học sinh), sourced from Unicode Unihan `kVietnamese` (Unicode licence — verify and register in `content/sources/registry.json`) plus a reviewed override list; one concept card per course on how to use it; a lint rule that every CJK lexeme with Han characters carries a Hán-Việt reading or an explicit "none". This is the single biggest advantage a Vietnamese learner has for ja/zh/ko.
- M4.4 (`P4c`) `ja-vi` + JLPT N5; M4.5 (`P4d`) `zh-vi` + HSK 1–2; M4.6 (`P4e`) `ko-vi` + TOPIK I.
- M4.7 (`P4f`, recommended) `en-vi` + VSTEP/TOEIC basics — English is the largest Vietnamese market; uses the same template with a Vietnamese-speaker pedagogy brief.
**DoD per course:** validators + claim gate; audio provenance; Vietnamese native review signed; device walk; exam-track mock test with honest wording.

## Phase 5 — Breakthrough features (≈8–12 weeks, parallelisable)  → prompts `P5a`…`P5f`
- M5.1 (`P5a`) FSRS visible + optimizer + gentle streak polish.
- M5.2 (`P5b`, **runs before M4.2**) Graded stories generator + reader + audio — the context layer for the daily-words stream (target: lint `syllabus-context` = 0 for `es-vi`), reused by every language.
- M5.3 (`P5c`) Own-text importer.
- M5.4 (`P5d`) Pronunciation coach: sherpa-onnx native module (Expo config plugin), model pack download manager, forced alignment + GOP, Vietnamese tips, English first; benchmark on speechocean762 subset; device tests.
- M5.5 (`P5e`) Mistake-driven grammar.
- M5.6 (`P5f`) Optional constrained LLM (on-device pack and/or BYO key) + privacy policy/Data safety updates + import-graph test.
**DoD:** each feature behind a flag, off by default until device-accepted; no network path without opt-in; docs/policy updated.

## Phase 6 — Brand, store, release (≈2–3 weeks)  → prompts `P6a`, `P6b`
- M6.1 (`P6a`) Brand/identity migration (D-3), store listing (vi/en), screenshots from the final RC, Data safety "No data collected" (+ opt-in declarations if Phase 5 shipped), website update, closed test plan (12 testers × 14 days), AAB `production` build via EAS or local bundle.
- M6.2 (`P6b`) Device acceptance full matrix (2 devices), accessibility A1–A15, soak, final RC exit gate, submission.
**DoD:** STORE READY → SUBMITTED → LIVE per `PUBLICATION_STATUS.md`.
