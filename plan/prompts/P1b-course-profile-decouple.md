# P1b — CourseProfile registry: remove every `fr-en` hardcode from the runtime

Read `CLAUDE.md`, then `plan/07-PRODUCT-SPEC.md` §3, `plan/08-ROADMAP.md`, and **`plan/02-AUDIT-ARCHITECTURE.md` §2 (the full coupling audit) and §10.5**. Create a task list listing every item of §2.1–§2.7 as a checkbox. Branch `phase-1/course-profile`. French behaviour must stay byte-identical: the golden tests from P1a are the contract. End with the REPORT block.

## Goal
Any course can opt into any French-layer capability through data, not code. After this milestone there is **no** `"fr-en"`, `FR_COURSE_ID`, `isFrench`, `FRENCH_LOCALE`, `frenchRecognitionAvailable`, `knownFrenchVocabulary`, `dueFrenchReviewQueue`, `undoLastFrenchReview` in `src/` except inside `src/lib/languages/fr.ts` and the frozen id map.

## Design (implement exactly; ask in the report if something cannot fit)
1. `src/content/course-profiles.json` **generated by the compiler** (add to `GENERATED_TARGETS`): one `CourseProfile` per pack — `id, targetCode, nativeCode, recognitionLocale, ttsLocale, script, idPrefix, flag, capabilities{fsrs, dailySession, lexicon, concepts, placement, checkpoints, goals, listening, reading, speaking, writing, conversation}, artifacts{lexiconIndex?, lexiconDb?, concepts?, objectives?, checkpoints?, placement?, attainment?, claim?, listening?, reading?, clipAssets?, speech?, writing?, scenarios?}`. Capabilities derive from which artifacts exist for the course's target + an explicit `enabled` override in a new `content/courses/<id>.profile.json` (so `es-en` can get `fsrs:true` later without rich artifacts). Today only `fr-en` has rich artifacts.
2. `src/lib/course-profile.ts`: `courseProfile(courseId)`, `hasCapability(courseId, cap)`, typed; replaces `capabilities.ts` (delete it). All UI gates (`(tabs)/_layout`, `(tabs)/index`, `(tabs)/practice`, `(tabs)/profile`, routes guards from P0) use it.
3. **Per-course artifact loaders** with static requires (Metro): generate `src/content/artifacts/<courseId>.ts` exporting typed getters; `src/lib/content-registry.ts` resolves `artifactsFor(courseId)`. `lib/assessment/content.ts`, `lib/reception/content.ts`, `lib/speech/content.ts`, `lib/writing/content.ts`, `lib/interaction/content.ts`, `lib/learning/concepts.ts`, `lib/learning/lexicon-index.ts`, `lib/lexicon/provider.ts`, `native-loader.native.ts` (one DB per language; cleanup must not delete other languages' DBs) all take `courseId`.
4. **Id registry**: `src/content/ids/<targetCode>.json` generated from `content/<target>/lexemes.json`; `src/lib/learning/ids.ts` exposes `itemIdFor(courseId, surface)`, `surfaceFor(courseId, id)`, `isCuratedItemId(courseId, id)`, `idPrefix(courseId)`. `ids-fr.ts` becomes a thin re-export used only by the drift test; the hand-maintained map is deleted once the generated one is proven identical (test).
5. **Language plugins** `src/lib/languages/{index,fr,en,es,de,it,pt,ja,ko,zh,vi}.ts` with interface `LanguageRules { code, articleCue(lexeme), splitArticle(surface), numberToWords?(n), digitsToWords(text), normalizeLenient(text), normalizeStrict(text), tokenize(text), fold(text), ttsLocale, recognitionLocale }`. `fr.ts` holds today's French logic (french-numbers, le/la/l', œ/æ folding). Others start with sane defaults (Intl.Segmenter when available on Hermes — verify and fall back to a bundled simple segmenter; tone-preserving strict normalise for `vi`). `grading.ts`, `speech/grader.ts`, `writing/rubric.ts`, `lexicon-search.ts`, `distractors.ts` call the plugin for the session's course.
6. **Engine/store**: `applyEvidence` routes on `capabilities.fsrs`; `dueReviewQueue(courseId, …)`; `undoLastReview(courseId)`; `submitEvidence` uses `definition.courseId` (and asserts it equals the active course); `today.ts`, `session/sources.ts`, `session/evidence.ts`, `session/panel.ts`, `review-builder.ts` (no default courseId) take `courseId`.
7. **Speech**: `probeSpeechCapability(locale)` memoised per locale; fields renamed `targetRecognitionAvailable`, `targetOnDeviceModelInstalled`; permission strings in `app.json` made language-neutral ("the language you are practising").
8. **UI copy**: replace literal "French" in components/screens with `profile.targetLanguage` (full i18n comes in P2a; this milestone only removes the hardcoded language name). `flag.tsx` reads the flag from the profile.
9. Scripts: `scripts/lib/pipeline.ts` gradeTargets for every course whose profile has `fsrs`; the "forbidden outside fr-en" rules become "forbidden unless the course has the capability/artifact" (schema generalisation itself is P1c; here only the gating changes).
10. Tests: every modified module gets/keeps unit tests; add `src/lib/__tests__/no-fr-hardcode.test.ts` that greps `src/` for the forbidden identifiers (allowlist `languages/fr.ts`, `ids-fr.ts`); golden suites must pass unchanged; jest integration suites updated for renamed APIs.

## Definition of Done
Golden tests pass without re-blessing; `no-fr-hardcode` test passes; `fr-en` jest + e2e unchanged; a throwaway test enabling `fsrs` on `es-en` via the profile override shows the Today tab and FSRS review working on Spanish words (not committed as product behaviour — keep it as a test fixture only); CI green; `plan/STATUS.md` updated.
