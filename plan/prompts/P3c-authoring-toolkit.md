# P3c — Authoring toolkit: LLM-assisted drafts that must pass the validators

Read `CLAUDE.md`, `plan/07-PRODUCT-SPEC.md` §5, **`plan/03-AUDIT-CONTENT.md` §2 (French structure and the RESEARCH.md rules), §5 (validators), §8**, `content/fr/*/RESEARCH.md`. Branch `phase-3/authoring-toolkit`. End with the REPORT block.

## Goal
A repeatable way to author a full French-parity course **from Vietnamese** for any target language with Claude's help — every learner-facing string (instructions, guidebooks, concept explanations, can-do, feedback cues, scenario goals) is written in Vietnamese per `STYLE-vi.md`, where every generated artifact is a **draft** that the deterministic validators and a native-review checklist must approve before compile. No network code in the repo: generation happens in Claude Code sessions (or the owner's chat) from prompt templates the toolkit emits; the toolkit ingests the resulting JSONL/JSON.

## Tasks
1. `plan/authoring/` (committed): a **course blueprint** `BLUEPRINT.md` that documents French's structure as the template (6 sections; per-section unit/lesson/exercise counts and types; objectives per domain; checkpoint composition; placement stages; reception caps; speech/writing/interaction constructs; claim-policy requirements) with the exact counts from the audit, and a `STYLE-vi.md` for Vietnamese learner-facing prose (register, grammar terminology, honesty rules, no CEFR descriptor text).
2. `bun scripts/author.ts <step> --target es --native vi` (same for de/it/pt/ja/ko/zh/en) emitting prompt bundles into `content/<target>/_drafts/<step>/PROMPT.md` + `INPUT.json`, and ingesting `OUTPUT.jsonl` back into authored files, for steps: `objectives`, `units` (sections 2–6 unit plan + guidebooks), `lessons` (exercises per lesson, referencing lexeme ids only), `concepts` (+ paradigm tables with evidence refs), `readings`, `listening` (scripts with speaker cast), `speech`, `writing`, `scenarios`, `checkpoints`, `placement`, `lexicon-review` (fills `TODO:vi`, examples, confusables from P3a). Each prompt embeds: the blueprint slice, the schema (zod → JSON schema via `z.toJSONSchema`), the allowed id lists (lexemes, objectives, clips), the style guide, and 2–3 French examples translated as exemplars. Each ingest step runs the relevant validator immediately and writes `content/<target>/_drafts/<step>/REPORT.md` (pass/fail per item with reasons) so the next Claude session can fix only the failures.
3. **Vietnamese pedagogy briefs** `plan/authoring/briefs/<target>-vi.md` (one per target; es/de/it/pt/ja/ko/zh/en/fr): what Vietnamese speakers find hard in that language (transfer errors, script, gender/case, tense marking vs Vietnamese particles đã/đang/sẽ, articles, final consonants, tones/pitch…), which jobs/exams drive demand, scenario list, exam-track format. These briefs are injected into every prompt bundle.
4. Review checklist generator: `content/<target>/REVIEW-CHECKLIST.md` listing every learner-facing string with a checkbox for the native reviewer, grouped by step; compile refuses a course until `content/courses/<id>.profile.json` has `review: {native: "<name>", date}` **or** `allowUnreviewed: true` with a `KNOWN_LIMITATIONS.md` entry (so we can ship beta content honestly).
5. Quality linters beyond the validators: answer-position balance, duplicate payloads, distractor plausibility (same POS/topic), guidebook length floor/ceiling, exercise-type mix per section vs blueprint, lexeme coverage (every lexeme taught ≥2 times, reviewed ≥ 1 time per skill), CEFR-descriptor leak check (string match against a small banned-phrase list — do not embed descriptor text), reading-level caps.
6. Dry-run on the synthetic `xx` language and on French (the linters must flag French's known issues from the audit: position bias, 5 duplicates, thin Section 5 guidebooks — do not fix French here; just prove the linters see them).
7. Docs: `content/README.md` "Authoring a course" section with the order of steps and the expected number of Claude sessions per step.

## Definition of Done
Toolkit runs end-to-end on `xx`; prompt bundles for `es/vi` generated for the `objectives` and `units` steps and committed under `_drafts/` (excluded from the app bundle); linters have tests; CI green; `plan/STATUS.md` updated.
