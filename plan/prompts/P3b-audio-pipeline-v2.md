# P3b — Audio pipeline v2: multi-engine build-time synthesis with the licence gate

Read `CLAUDE.md`, **`plan/06-RESEARCH-OPEN-RESOURCES.md` §2 (TTS) and the licence notes**, `plan/03-AUDIT-CONTENT.md` §3, `scripts/pack-audio.ts`, `scripts/reception-audio.ts`, `scripts/lib/piper-audio.ts`, `scripts/audio-asr-audit.py`, `.github/workflows/pack-audio.yml`, `.github/workflows/reception-audio.yml`, `release/AUDIO_PROVENANCE_FINAL.md`. Branch `phase-3/audio-v2`. End with the REPORT block.

## Goal
One dispatch-only workflow can synthesise, QA, and apply pack + reception audio for any language with any of: Piper (classic MIT engine, per-voice licence), Kokoro-82M (Apache-2.0), MeloTTS (MIT). Voice selection stays canary-driven with an ASR round trip (Whisper; SenseVoice for zh/ja/ko only — Vietnamese audits with Whisper, SenseVoiceSmall has no Vietnamese). The first run produces Spanish pack + lexicon + reception audio with two licence-clean voices, and the canary/selection report is produced for **all 8 targets** so every later course knows its voice cast up front. French stays byte-identical.

## Tasks
1. `scripts/lib/tts/` engine abstraction: `TtsEngine { id, install(venv), listVoices(), synth(text, voice, outWav) }` for `piper`, `kokoro`, `melotts`; pinned versions and model hashes in `content/audio/engines.json`; every voice entry carries `licence` parsed from its model card/README with the existing fail-closed gate (allow CC0/PD/CC BY 4.0/CC BY-SA 4.0/Apache-2.0/MIT **for the dataset/voice licence**; deny GPL/AGPL/NC/ND/unknown; OpenRAIL/Gemma-style use-restricted models are not allowed for shipped audio).
2. Manifest v2: `content/audio/pack-audio-manifest.json` gains `engine` per voice and per-course `voiceCast {A, B}`; reception manifests per language `content/<lang>/reception/audio-source-manifest.json` with the same shape.
3. ASR audit: `scripts/audio-asr-audit.py --lang` chooses faster-whisper (default, including vi) or SenseVoice (zh/ja/ko only: SenseVoiceSmall knows zh/yue/en/ja/ko and emits Chinese filler for Vietnamese — the 2026-10-14 vi canary scored WER 1.0 on every clip for that reason) and uses the language plugin's normaliser + CER for ja/zh; thresholds unchanged (review ≥ 0.5 WER/CER on ≥3-token clips; selection fails > 0.6).
4. Technical QA extended with `charsPerSecBand` from the plugin and a loudness normalisation step (EBU R128 to −18 LUFS integrated) so engines mix evenly; keep 64 kbps MP3 22.05 kHz mono; keep the content-addressed key (bump `pipelineVersion` only for new languages so French keys do not change).
5. Workflow `audio.yml` (replaces both): inputs `mode=recon|canary|generate`, `lang`, `courses`, `layer=pack|reception|all`; apply step regenerates `src/content/audio-manifest.ts` and `<lang>-clip-assets.ts` **only for the languages listed** (fix the "apply rewrites the whole manifest" footgun by merging per language); baseline re-bless per language file (`content/audio/baseline/<lang>.json`); commits with a provenance note; `check-audio` reads all baseline files.
6. Voice casts for all 8 targets (recon + canary, selection recorded in `content/audio/voice-casts.json`): es — Piper `es_MX-claude` (Apache-2.0) + `es_ES-davefx` (CC0) or Kokoro es (Apache); decide Latin-American vs Castilian by the course text (pack is Latin-American → prefer es_MX for A, Kokoro/davefx for B and document); de — Piper thorsten + kerstin (CC0); it — Kokoro it ×2 (Apache); pt — Piper faber + cadu (CC0, pt-BR); fr — unchanged (siwis + upmc); ja — Kokoro ja or MeloTTS-JP (MIT); zh — MeloTTS-ZH (MIT) or Kokoro zh; ko — MeloTTS-KR (MIT); en (for P4f) — Kokoro en ×2; vi (UI/explanation audio if ever needed) — Piper `vi_VN-vais1000` (CC BY 4.0). Canary files per language `content/<lang>/reception/audio-canary.json` written with language-specific traps (liaison/elision fr; ñ/rr/diphthongs es; umlauts/final devoicing de; doubled consonants it; nasal vowels pt; long vowels/geminates/pitch ja; tones zh; batchim/tensing ko). Generate Spanish pack audio for every speakable string in `content/courses/es-vi.json` once P3d lands, and lexicon audio (new `layer=lexicon`) for the Spanish lexicon surfaces + examples now.
7. Registry entries for engines/voices; `release/AUDIO_PROVENANCE_FINAL.md` → per-language provenance tables; model cards copied under `content/audio/model-cards/<lang>/`.
8. Local dev convenience: `bun scripts/audio.ts plan --lang en --dry-run` works offline; a `docker/audio.Dockerfile` (optional) for running the pipeline on the owner's PC when GitHub Actions minutes are a concern (note it in the docs; do not require it).

## Definition of Done
French audio baseline unchanged (hash-identical files); Spanish lexicon audio generated with 0 technical failures; canary reports + `voice-casts.json` committed for all 8 targets (with 'no clean voice' explicitly recorded where true); `audio:check` green with multi-file baselines; licences registered; `plan/STATUS.md` updated.
