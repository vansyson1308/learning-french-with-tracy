- **Learner store (`src/lib/persistence/learner-types.ts`, `learner-sql.ts`, `learner-json.ts`, `learner-db.ts` / `learner-db.native.ts`, `learner.ts`).** One `LearnerStore` interface (`loadCourse`, `commit`, `counts`, `exportAll`, `replaceAll`, `getMeta/setMeta`) with two implementations: `SqlLearnerStore` over an executor contract (`run/all/first/transaction`) — on device expo-sqlite `learner-v4.db` (WAL, exclusive transactions), in tests `bun:sqlite` through the same SQL; and `JsonLearnerStore` (one AsyncStorage document, web + fallback). Schema: `meta`, `cards (course_id, item_id, skill, state_json, due, updated_at)`, `review_log (seq, course_id, at, card_key, session_id, exercise_id, attempt_index, entry_json)` with a UNIQUE identity index — log rows have an identity (`LogRef`), so replay/import are idempotent (`INSERT OR IGNORE`). Memory keeps only the active course's cards and its most recent 2,000 log entries (`LEARNER_LOG_WINDOW`); the ring cap in memory is unchanged.
- **Write path.** Every scheduler mutation (`submitEvidence`, `undoLastReview`) becomes a delta (`cardUpserts`, `logAppends`, `logRemovals`) in a pending buffer persisted at once under `learner-pending-v4`; `flushLearner()` commits it as ONE transaction at session completion (`session/controller.ts`), on export and before any course load; a crash-left buffer is replayed before anything else on the next launch. Undo removes the log row by identity and restores the card.
- **One-time import.** `bootstrapLearner()` (run after every rehydration, `runLearnerBootstrap()` / `whenLearnerReady()`): replay → if the blob still carries cards or a log, write `progress-before-v4-<stamp>.json` to the documents directory, import in one transaction, verify counts, record `blobImportedAt` → load the active slice; the blob is then written without cards/log (`partializeForPersist`). Idempotent (a crash before the strip re-imports nothing twice); 10,000 entries + 800 cards import in ≈ 200 ms on bun:sqlite (budget 2 s). Fail-soft: a broken store never blocks readiness (`learnerReady`); `_layout` waits for `hasHydrated && learnerReady`. The bootstrap is skipped when rehydration itself failed (no storage — the static-export render pass).
- **Backup v2 (`backup-core.ts`, `backup.ts`).** Envelope `envelopeVersion: 2` = `state` half (blob, stripped) + `learner` half (`{cards, reviewLog}` pulled from the store after a flush) + manifest counts; v1 envelopes (cards/log inline) still import — their learner data is split out in scratch; `runInvariants(state, now, learner?)`. `commitImport(state, learner)`: safety copy `progress-before-import-<stamp>.json` + rollback file (both halves) → memory learner data reset → store `replaceAll` → blob write → rehydrate + bootstrap → read-back verification of both halves (field by field, not byte by byte) → rollback file deleted; any failure restores BOTH halves.
